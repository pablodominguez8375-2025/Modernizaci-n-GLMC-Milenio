# Proyecto Milenio v1.0.0-rc1

**Canal:** Release Candidate  
**Destino:** Piloto Operacional  
**Base consolidada:** funcionalidades e infraestructura desarrolladas hasta v0.33.

## Resumen

v1.0.0-rc1 es la primera versión candidata integral de Proyecto Milenio para validación operacional. Su objetivo es congelar una base técnica reproducible sobre la cual ejecutar UAT institucional, bootstrap controlado y controles de salida antes de promover una v1.0 estable.

Esta RC no constituye autorización automática para cargar datos personales reales ni para una puesta en producción definitiva.

## Incluido

### Núcleo institucional

- ficha maestra de personas/miembros y pertenencias históricas;
- grados, cargos y estados institucionales;
- transferencias entre Talleres preservando historial de origen y continuidad del grado;
- ficha 360 de miembro y Taller;
- reportes y control operacional de Régimen Interior;
- calidad de datos y cola de corroboración.

### Ceremonias y Gran Secretaría

- motor de elegibilidad de ceremonias;
- validación por Régimen Interior, Gran Tesorería y Gran Hospitalaria;
- publicación de insinuados con plazo configurable;
- autorizaciones formales;
- gestión de espacios y reservas;
- proyección al calendario institucional.

### Gestión Logial

- tenidas, actas, asistencia y docencia;
- perfiles de Taller con permisos acotados a su organización;
- historial institucional sin sobrescritura destructiva.

### Documentos y conocimiento

- Gestor Documental con versiones y almacenamiento de objetos;
- controles de integridad, tipo de archivo y ClamAV;
- Biblioteca Virtual con acceso por grado/permisos;
- Gran Archivero para patrimonio documental histórico, separado de Biblioteca Virtual;
- las planchas de trabajo no forman parte del Gran Archivero;
- CENDOC permanece fuera del alcance de Proyecto Milenio.

### Servicios transversales

- notificaciones institucionales persistentes;
- calendario institucional unificado como proyección de fuentes maestras;
- masking `Ocupado` para eventos protegidos;
- reportería ejecutiva;
- auditoría transversal;
- localización es-CL y zona horaria America/Santiago.

### Seguridad, privacidad e infraestructura

- Keycloak / OIDC Authorization Code Flow + PKCE S256;
- cliente piloto sin password grant;
- `platform_superadmin` separado del Administrador de Gran Logia;
- PostgreSQL;
- MinIO/S3 privado;
- ClamAV;
- Docker Compose para first implementation y piloto;
- gateway HTTPS;
- backup, verificación, restore y recovery drill;
- privacy gate, clasificación de datos y migration safety gate;
- línea base técnica de preparación para Ley 21.719.

### Bootstrap v0.33

- dry-run antes de aplicar;
- aplicación transaccional e idempotente;
- hash SHA-256 del paquete;
- rechazo de mutación de una versión ya aplicada;
- paquete inicial con Gran Logia Mixta de Chile y Respetable Logia Libertad Nº 23;
- separación entre perfiles de seguridad y cargos institucionales/ritualísticos;
- sin personas, RUT, correos, teléfonos ni credenciales en el paquete versionado.

## Cambios propios de la RC

- backend versionado como `1.0.0-rc1` desde el proyecto .NET;
- `/api/system/info` obtiene la versión del assembly y no de un literal manual;
- manifest `release/PMGM-RELEASE-1.0.0-rc1.json`;
- nuevo `tests/release_gate.py` para validar coherencia de versión, piloto, OIDC, bootstrap y gates CI;
- smoke Bash y PowerShell alineados con el manifest de release;
- checklist explícito para promoción y rollback.

## Limitaciones / pendientes antes de v1.0 estable

- UAT institucional aún debe aprobarse formalmente;
- dominio y TLS definitivos del entorno objetivo deben validarse;
- secretos reales deben provisionarse y rotarse fuera de Git;
- backup/restauración debe verificarse en el servidor objetivo;
- el bootstrap debe ejecutarse en el entorno piloto después de un dry-run limpio;
- antes de incorporar datos personales reales se requiere revisión organizacional/legal de privacidad, conservación y responsabilidades;
- esta RC no implica que todos los módulos futuros del plan maestro estén implementados.

## Criterio de aceptación técnica

La RC sólo se considera técnicamente válida cuando los cinco jobs de PMGM CI terminan verdes sobre el mismo SHA:

- Backend build and tests;
- Frontend lint and build;
- Infrastructure configuration;
- First implementation authenticated smoke;
- Pilot operational HTTPS and recovery.

La promoción posterior a `v1.0.0` estable requiere además la aceptación operacional documentada en `docs/instalacion/PMGM-RELEASE-CANDIDATE-V100-RC1.md`.
