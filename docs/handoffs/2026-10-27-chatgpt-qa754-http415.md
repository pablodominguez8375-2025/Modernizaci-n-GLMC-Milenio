# QA #754 — Corrección HTTP 415 al crear usuario sintético — 27-10-2026

## Antecedente físico y diagnóstico sustentado
El Sponsor confirmó que, tras activar exclusivamente la identidad de API en glmdch con operador #761 (14:26 UTC), el botón «Crear usuario y enviar clave inicial» se habilitó al seleccionar hermano sintético de un Taller, pero el POST produjo mensaje **«La API respondió 415 Unsupported Media Type»**. No existe evidencia de creación de identidad ni de envío de correo inicial en este intento; no repetir POST hasta desplegar corrección. La captura de cabeceras físicas no está disponible, por lo que el origen exacto del 415 no está confirmado con traza de tráfico; sin embargo el código prueba un defecto suficiente para explicarlo.

En `dev@cf8e9db720bf27fb066ef1593ebc72d43de425c1` y en QA física previa, `frontend/src/api/pmgmApi.ts` hacía `this.request('/api/system/user-accounts',{method:'POST',body:JSON.stringify(request)})` sin `Content-Type`. Su envoltorio `request` añade `Accept: application/json` y `Authorization: Bearer`, no `Content-Type`; un body string de Fetch puede salir como `text/plain;charset=UTF-8`. ASP.NET Core en `backend/src/PMGM.Api/Modules/UserAccounts/UserAccountEndpoints.cs` hace binding de `CreateUserAccountRequest` y puede responder 415 antes de invocar el handler, sin implicar problema SMTP/Keycloak.
