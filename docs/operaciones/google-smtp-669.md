# #669 — Correo SMTP Google configurable en Parámetros
Fecha 23-10-2026. Código PR #670 a dev. No desplegar secrets a GitHub, Google Drive ni logs.

## Configuración operativa
1. Administrador del servidor API: suministrar `SystemMail__EncryptionKey` como **clave aleatoria de 32 bytes en base64**, fuera del repositorio y protegida, accesible exclusivamente al proceso de API. No copiar ni mostrarla en chats; incluirla en procedimiento de recuperación/rotación bajo custodia técnica. Sin esta clave, el API rechaza guardar contraseña (409) y no descifra credenciales antiguas. El cifrado usa AES-256-GCM con nonce aleatorio y AAD ligada al servicio.
2. Cuenta Google Workspace/Gmail autorizada: si es posible usar contraseña de aplicación, habilitar verificación en 2 pasos y crear contraseña específica en la cuenta; **no utilizar la contraseña habitual de Google**. Si la política organizacional no permite contraseñas de aplicación, la siguiente etapa debe implementar OAuth2/XOAUTH2 o usar relay de Workspace configurado por administrador, sin debilitar TLS.
3. En **Parámetros → Correo electrónico**, guardar mediante el editor versionado `system.mail.smtp_host=smtp.gmail.com`, `system.mail.smtp_port=587`, `system.mail.sender_address=cuenta completa`, `system.mail.security=STARTTLS` y nombre de remitente. Estos NO son secretos y siguen el control de versiones de parámetros. Guardar la contraseña **separadamente** en el bloque Clave SMTP, que nunca revela ni versiona la clave en el catálogo genérico.
4. En el mismo bloque, escribir un destinatario de prueba que usted controle y pulsar **Enviar correo de prueba real**. El servidor autentica mediante STARTTLS y sólo informa Google aceptó el correo para entrega si `SmtpClient.SendMailAsync` completó exitosamente; el resultado no garantiza recepción en bandeja (filtros de spam, etc.). Verificar destinatario y auditar el evento sin registrar secreto ni dirección del destinatario.
5. El alta de nuevos usuarios usa primero la configuración segura de Parámetros cuando existe y está vigente; conserva compatibilidad con las variables de entorno originales de SMTP para no bloquear despliegues existentes. Recuperación de clave de Keycloak usa su SMTP propio y deberá configurarse por separado.

## Contrato y privacidad GOV-004
Datos persistentes: `core.institutional_rule_settings`, código interno `system.mail.smtp_secret.protected` (no forma parte del catálogo ni GET/versiones), valor `g1:` + base64(iv[12],tag[16],ciphertext), referencia técnica sin secreto, operación protegida por `CanConfigureSystem`. **Nunca guardar contraseña en `system.mail.*` visible** ni incluir en auditorías. Endpoints nuevos: GET /api/system/mail/credentials (solo estados bool), POST /api/system/mail/credentials ({password}, nunca regresa secret), POST /api/system/mail/test ({recipient}, envío real). No hay DDL ni nuevas tablas.

## Estado y límites
Probar funcionamiento en QA sin credenciales reales hasta que administrador configure el proceso y confirme envío mediante buzón controlado. El QA actual puede demostrar interfaz sin prueba de conexión externa. Fase actual sólo Google smtp.gmail.com:587; puerto 465 SSL implícito y smtp-relay.gmail.com requieren implementación explícita distinta. No abrir proxy SMTP arbitrario. Los secretos reales jamás se comparten en GitHub o Drive.
